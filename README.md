# Dex2OAT Manager v1.6.4

Android 16 / KernelSU 专用 ART 编译管理器源码。项目保留 v1.2 的四页布局。

## 新增

- 启动和返回前台自动 `su -c id` 检测 Root。
- APP 页面展示目标模式及 `pm art dump <package>` 解析的实际编译模式；长按应用查看 ART 原始详情。
- 应用页面选中后可批量 `pm compile --reset`。
- 任务详情可勾选包名、全选后进行编译重置。
- 自定义分组可切换用户应用 / 系统应用、搜索、全选当前筛选结果，实时显示选中数。跨组冲突仍被禁止。
- 概览分别统计历史成功数与当前已达标数，ART 未知不算已达标。
- 自动增量编译读取系统 ART 状态后判断；Profile 回退 verify 时可暂缓重试。
- 命令输出保存在历史记录，所有执行操作都经 KernelSU `su`。

## 操作注意

- Android 16 AOSP 标准 ART Service 支持 `speed`, `speed-profile`, `verify` 三种模式。本版新增 `everything` 作为**实验性兼容选项**，系统可能拒绝，不保证可用。失败会如实记录，绝不自动替换为 speed。
- `pm compile --reset` 将优化产物重置至安装时状态，**不会**清空应用数据，但仍有系统稳定性风险。优先测试普通应用。
- ART 状态是按包解析多 dex 的输出，如果返回多种编译状态会显示为“混合”，不会误认为已达标；无法解析显示“未知”。
- 定时任务使用 WorkManager，受 Android / ColorOS 后台限制。
- 真实设备上的 `pm art dump` 输出和 KernelSU 授权行为需要在真机验证。

## 构建

GitHub Actions: `.github/workflows/build.yml`，使用 JDK 17，Gradle 8.13，Android SDK 36。项目未携带 Gradle Wrapper，CI 使用 setup-gradle。

> 此环境不存在完整 Android SDK / Gradle，未运行 `assembleDebug`，所以 **不保证本版本已编译成功**。使用 GitHub Actions 验证后以真实构建结果为准。


## v1.4.0 UI 和分组操作

- 概览：独立任务状态卡片、停止按钮、双列快捷操作与达标统计。
- 应用：用户/系统应用双 Tab、紧凑分层卡片、双列批量操作，移除全局“包含系统应用”开关。
- 策略：全局模式与定时周期均为单行选择+保存；分组标题右侧新增按钮。
- 分组：固定 380dp 高滚动区，分组卡片展示数量/确认不匹配数/未知数，四个并排按钮：刷新、编译、编辑、删除。
- 分组编译：刷新后仅处理 ART 状态**已确认不匹配**的包，状态未知不会强制编译；最后仍由引擎执行增量校验。
- 点击反馈：按钮使用 Ripple 和短时缩放动画，耗时操作附 Toast；任务是否运行在概览显示。

注意：本交付是 Android Studio 源码工程；当前生成环境没有 Android SDK，未能运行 assembleDebug。建议在 GitHub Actions 编译并以构建日志确认。

## v1.6.0 界面与扫描优化

- 全局 ART 扫描期间锁定概览导航；尝试进入其他页面会提示扫描进行中。
- 应用管理移除列表标题和搜索栏；操作按钮上移；用户/系统应用以整行等宽 Tab 展示，应用列表限定 450dp 高度独立滚动。
- 自定义分组列表限定 380dp 独立滚动；任务历史和实时日志分别限定 340dp 与 280dp 独立滚动。
- 编译和重置结束后，解析任务 `details`，只对返回成功的包名重新读取 ART 状态，不再触发 `scanArt()` 全量扫描。跳过项和失败项不进行额外状态读取。
- 增量应用扫描入口从概览移到应用管理；概览删除任务记录快捷按钮。记录仍通过底部「记录」Tab 访问。
- 注意：首次启动或手动「刷新全局 ART」仍会完整扫描。后台 WorkManager 的增量判定独立于前台 ART 状态缓存。

构建验证：当前交付环境未安装 Android SDK，尚未真实运行 Gradle assembleDebug；项目 ZIP 和静态代码检查不等同于 Android 编译通过。


## v1.6.1 变更
- 编译/重置/ART 查询统一互斥；浏览页面、分类切换、勾选及分组配置不被任务锁阻止。
- 手动 ART 全量查询、分组查询和编译操作增加确认；自动后台任务不弹框。
- 用户/系统应用独立勾选与计数，顶部 Root 状态；取消扫描锁页。
- 应用、分组、历史记录采用 RecyclerView；嵌套滚动区域拦截触摸，列表紧凑布局。
- 开始任务时固化执行包名快照；后台 WorkManager 仍共用 Engine 互斥。

注意：源码包仅经过静态检查，当前容器无 Android SDK/Gradle，尚未完成 assembleDebug。

## v1.6.2

- 全局模式和自定义分组新增 everything（实验性）选项，保留原三种。
- ART 状态解析增加 everything 标记兼容。
- 实际编译仍通过 `cmd package compile -m everything -f <package>`，设备不支持时显示失败，不自动降级。
- 强烈建议先以单个普通应用测试，再考虑全局或自动任务；不建议默认设为 everything。

## v1.6.3 界面与任务控制更新

- 概览：移除“编译概览”标题；总数/已完成/待处理/未知四列可点击查看当前缓存的应用与编译模式（只读，不发起 ART 查询）。
- 当前任务：编译和 ART 状态刷新期间均可发送停止请求；ART 扫描在收到请求后停止查询后续包名，正在执行的一次 `su` 查询可能需要短暂退出。
- 应用：移除“应用管理”标题；用户/系统应用改为一个共用底座的等宽双 Tab。
- 策略：改为“全局默认编译模式”、“开启自动周期扫描”、“新建编译分组”；删除多余的分组章节标题。
- 记录：移除“任务执行记录”标题。

已做源代码结构与 Java 语法层面的检查，当前环境不包含 Android SDK / Gradle，**未实际执行 Android APK 编译**。
